# PROJECT_RULES.md — animation-motion

Правила проекта. Универсальные правила исполнителя — в AGENTS.md. План этапов — docs/motion-roadmap.md. Идеи и чужие источники — docs/IDEAS.md.

## Продукт
Локальный комбайн: текст ролика → сцены → графика из кода и лёгкие анимации → видео (YouTube, TikTok). Без видеокарты и платных подписок. Первая тема: «Что если бы киты летали». Один общий стиль на все сцены. Движок потом расширяется 3D-моделями (Three.js, glTF).

## Стек
- TypeScript + Vite, без фреймворков (редактор на чистом TS). Рендер: Canvas 2D; Three.js только с этапа 9.
- Node-скрипты для экспорта, ffmpeg для сборки MP4 (Node.js и ffmpeg на машине владельца уже стоят).
- Платформа владельца: Windows, ноутбук (RTX 3050 4 ГБ, 16 ГБ ОЗУ). Не рассчитывать на мощную видеокарту.
- Новые зависимости только по согласованию с тимлидом.

## Папки (создаются по этапам)
`engine/` рендер без UI · `editor/` интерфейс · `catalog/` модели JSON · `scenes/` сцены JSON · `tools/` скрипты (экспорт, конвертер) · `tasks/` задания · `docs/` документы · `reference/` эталоны, только чтение (там `reference/m0/scene-sandbox.html` — исходный прототип).

## Правила рендера (нарушать нельзя)
1. Кадр = чистая функция от времени `t` и сцены. Время приходит параметром.
2. В коде рендера запрещены `Math.random`, `Date.now`, `performance.now`. Случайность только через генератор с seed (`params.seed`).
3. Мировые единицы: высота кадра = 1000, центр (0,0), ось y вниз. Размеры в сценах задаются в этих единицах, реальные размеры объектов хранятся в метрах отдельным полем.
4. Слои рисуются в порядке списка (первый самый дальний). `depth` задаёт параллакс: 0 фон, 1 плоскость действия, больше 1 передний план.
5. Все цвета берутся из `palette` (слоты) или `#hex`. Стиль один; смена настроения = смена палитры.
6. Форматы 16:9 и 9:16 должны работать оба; на раннем этапе проверяем минимум, масштаб добавляем позже.

## JSON-контракт сцены (v1, из прототипа M0)
Корень: `version, title, duration, palette, style{grain,vignette,preset}, camera{verticalFit, keys[{t,x,y,zoom}]}, assets, layers[]`.
Слой: `{id, name, depth, visible, objects[]}`. Объект: `{id, name, kind, x, y, s, rot, alpha, color, params, anim[], partAnim}`.
`kind`: `sky | glow | cloud | skyline | asset`. `anim[].type`: `move | drift | bob | swing | pulse | fade` (move задаёт смещения от x,y).
У каждого слоя и объекта обязательны уникальные `id` и понятное `name` (редактирование как в векторном редакторе).
Схему менять только по заданию тимлида. Изменение схемы = повышение `version` + миграция. Сцены и модели существуют только как JSON.

## Ручной режим ИИ
Всё, что делает ИИ, должно работать и без него: сцену можно выгрузить как JSON с описанием формата, отдать любой модели и вставить ответ обратно. ИИ-провайдеры только бесплатные (Gemini, Groq и т.п.), ключи не хранить в репозитории.

## Визуальная проверка
Для задач про рендер и сцены в отчёте: PNG кадров сцены в t=0, середина, конец, в 16:9 и в 9:16, плюс сравнение с эталоном (`reference/m0`, пока задача не меняет вид). Файлы сохранять в `out/` (не коммитить).

## Каталог паттернов (баги, решения)
- Запуск Chrome из скриптов: всегда свой временный --user-data-dir, останавливать только свой PID, никогда по имени процесса. Иначе закрывается обычный Chrome владельца (все окна).
Пока пусто. Новый тип бага или решения тимлид записывает сюда.

## Браузеры и процессы
- Агент не запускает браузеры (Chrome/puppeteer) и не завершает процессы (по имени или PID) без явного разрешения в задании.
- taskkill, pkill, killall и Stop-Process по имени образа запрещены всегда.

- run.bat и stop.bat принадлежат владельцу; taskkill в stop.bat по PID из .run/dev.pid разрешён; агент их не меняет и не запускает.
