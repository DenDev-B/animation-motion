# Очередь этапа 5 «Комбайн: каталог, импорт, пресеты движения, идея → проект» (05-01 → 05-08)

Заменяет очередь этапа 4: файлы 04-01…04-06 и README-stage4.md удалить из tasks/ (04-00 выполнено и принято).

## Цель владельца
Комбайн по созданию роликов, а не приложение для одного ролика. Владелец пишет идею, получает проект из нескольких сцен (один рассказ), нужные объекты берутся из каталога приложения, а недостающие добавляются из готовых бесплатных наборов (SVG) или рисуются ИИ. Всё добавленное остаётся в приложении для всех будущих роликов.

## Решения архитектора (окончательные)
- Модель каталога = расширенный CatalogAsset (тот же формат, что у `kind: asset` и `kind: shape`). Старые модели и сцены остаются валидными и рендерятся побайтно как раньше (SHA контактного листа whale-demo 894D19CD… не меняется).
- Позы и клипы (морф) ОТКЛАДЫВАЮТСЯ. Анимацию импортированных объектов даёт пресет движения (05-05), а не ручные позы.
- 2D силуэты и пути. Меши/glTF и 3D не делаем (этап 9). Поле `mesh?: unknown` можно оставить как заготовку без реализации.
- Источники графики: бесплатные наборы SVG. Владелец сам скачивает файлы в папку `assets-src/` (агент из сети ничего не качает). Лицензия каждого файла записывается в модель (имя лицензии, автор, источник, ссылка). Для лицензий с обязательным указанием автора приложение собирает список титров.
- Свой парсер SVG, без новых npm-зависимостей. Если парсер упирается в неподдерживаемую функцию SVG, то он НЕ молчит: выдаёт понятное предупреждение или ошибку.
- Запись в каталог из интерфейса идёт через dev-сервер Vite (небольшой плагин, только localhost, только папка `catalog/`).
- Никаких обращений к ИИ-сервисам из кода: только текст туда и обратно.

## Как работать маленькими сессиями (важно: лимит агента небольшой)
- Выполняй задания строго по порядку, сколько позволяет лимит. Каждое задание заканчивается коммитом.
- Если чувствуешь, что лимит заканчивается, не оставляй работу в рабочем дереве: сделай коммит в ветку `wip/<номер>` (`git switch -c wip/05-03`, `git add -A`, `git commit -m "WIP 05-03: ..."`, затем `git switch -`) и в последнем сообщении напиши, что уже сделано и что осталось.
- Первым действием новой сессии проверь `git status`, `git branch` и наличие ветки wip/*; если есть незавершённая работа, продолжай с неё.

## Общие правила (на каждое задание)
- Прочитай AGENTS.md, PROJECT_RULES.md, docs/SCHEMA-v1.md и файл задания. Один коммит на задание: "<номер>: <кратко по-русски>". Push не делать.
- Браузер и Chrome не запускать, процессы не завершать (run.bat и stop.bat не трогать), зависимости не добавлять. Русский текст в файлы писать только через редактор/Node, не через PowerShell-перенаправления.
- Перед коммитом: typecheck, build, `npm run check` (включая check:text) и проверки задания. Красное не коммитить; после двух неудачных попыток остановись на задании.
- Описание формата вносить в engine/spec.ts и пересоздавать документы (`npm run docs:schema`), `check:docs` проходит.
- Старые сцены, проекты и SHA контактного листа whale-demo не меняются. M0 6/6 EXACT.
- Статусы: «сделано» / «запущено и проверено» / «не проверено».
