# Задание 03-02 (версия 2): единое описание формата и круг «копировать → ИИ → вставить»

## Цель
Главное для владельца: любой JSON (сцену, проект, объект) можно скопировать, отдать любому ИИ вместе с понятным справочником, получить ответ и вставить обратно с проверкой и внятными ошибками. Для этого формат описывается ОДИН раз (spec), а валидатор, справочник и подсказка для ИИ строятся из него.

## Сделать
1. `engine/spec.ts`: декларативное описание формата. Для каждого kind (sky, glow, cloud, skyline, asset) список params: имя, тип (number|int|bool|string|color|enum|array|object), min, max, default, краткое описание по-русски. Типы анимаций (move, drift, bob, swing, pulse, fade) с параметрами. Палитра (слоты), камера, стиль. ВАЖНО: `skyline.params.windows` это bool (как в существующих сценах), не число. Значения по умолчанию в spec должны совпадать с теми, что реально используются в рендере (сверь по коду).
2. Валидатор берёт проверку params из spec. Остальные правила добавить (нарушение существующих сцен недопустимо, при конфликте остановись и опиши): anim: period > 0 для bob/swing/pulse; ease из sine|inOut|out|lin; t0 <= t1 у move/fade; fade from/to в 0..1; camera: zoom > 0, ключи по возрастанию t без дублей; object: s > 0, alpha 0..1; style: grain и vignette 0..1; цвета `#rgb`/`#rrggbb`/`#rrggbbaa` (длина 3, 6 или 8). Неизвестный kind: ошибка со списком допустимых.
3. Сообщения об ошибках по-русски в виде «путь: что не так; допустимо: …; пример: …». Форму результата валидации сохранить (добавить поля, ничего не убирать), потребители не ломаются. Неизвестные ключи объекта/слоя/сцены дают `warnings`, не ошибки.
4. `validateAsset(json)` для catalog/*.json и inline-моделей: version/id/name (для inline необязательны), bounds (4 числа, w>0, h>0), parts не пусто, уникальные id частей, допустимые type (path, line, circle и то, что реально используется в kinds.ts), типы полей d/cx/cy/r/off/fill/rim/stroke/anim. Подключить в check-schema, загрузку каталога в export и contact-sheet.
5. `engine/ai-io.ts` (чистые функции, без DOM и Node API, чтобы работали и в CLI, и в редакторе):
   - `buildPrompt(json, {task?, scope?})` -> текст для чата ИИ: роль («редактор JSON-сцен, отвечай только одним JSON»), краткий справочник формата из spec, жёсткие правила (не менять version, не менять и не дублировать id, не добавлять комментарии, цвета только hex или слоты палитры, все числа в допустимых диапазонах, анимации детерминированы, никакой случайности кроме seed), текущий JSON, строка «Задача: …» (task или пустое место для ручного ввода). 
   - `extractJson(text)` -> терпимо достаёт первый JSON-объект из ответа ИИ: убирает обёртку ```json … ```, текст до и после, висячие запятые не чинит, но даёт внятную ошибку разбора с позицией (строка:столбец) и признаком «похоже, ответ обрезан».
   - `buildFixRequest(json, errors)` -> текст «исправь эти ошибки, верни ТОЛЬКО JSON целиком» со списком ошибок и исходным JSON.
6. `docs/SCHEMA-v1.md` генерируется из spec: `npm run docs:schema` (справочник на русском: поля сцены, каждый kind и его params с диапазонами и значениями по умолчанию, anim, камера, палитра, правила, два коротких примера JSON). `npm run check:docs` пересоздаёт файл в памяти и сравнивает с лежащим (файл должен быть актуален). Добавить в `npm run check`.
7. CLI: `npm run ai:prompt -- <scene.json|project.json> [--task "..."] [--scene N]` пишет out/ai/prompt.md (если проект и размер больше 60 КБ, предупредить и подсказать `--scene N`). `npm run ai:apply -- <ответ-ИИ.txt|json> [--into <файл>] [--scene N]`: достаёт JSON (extractJson), валидирует; при ошибках печатает их по-русски и пишет out/ai/fix-request.md (buildFixRequest); при успехе пишет `<имя>.applied.json` рядом (исходный не затирать) и печатает `warnings`.
8. `check:roundtrip` (в `npm run check`): prompt содержит исходный JSON и справочник; ответ в ```json обёртке проходит apply; обрезанный JSON даёт ошибку «обрезан» с позицией; сцена с неверным диапазоном даёт fix-request с путём ошибки; ответ с лишним текстом до и после JSON проходит.
9. Негативные тесты на каждое новое правило валидатора (минимум 20 случаев) и позитивный на все существующие scenes/*.json, projects/*.json, catalog/*.json.
