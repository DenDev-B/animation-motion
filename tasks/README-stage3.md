## Решения архитектора (окончательные)
- `skyline.params.windows` это boolean. Старые сцены не менять и не мигрировать.
- Смена сигнатуры `locateFrame` в 03-08 РАЗРЕШЕНА: обновить все потребители (export, contact-sheet, editor, check-project и тесты) в том же коммите.
- Недостающие фикстуры агент создаёт сам в том задании, где они нужны; зависимость от чужих фикстур запрещена. Если scenes/fixtures/ нет, создать каталог.
- Приоритет владельца: JSON виден, копируется, уходит в любой ИИ и возвращается с проверкой. Интерфейс вторичен. Шрифты в роликах пока неважны: использовать системный sans-serif, ничего не скачивать и не встраивать.
- Новые сущности этапа 3 это новые `kind`; слой остаётся группой с depth.
- Новые kind описываются в `engine/spec.ts` (см. 03-02): валидатор, `docs/SCHEMA-v1.md`, ИИ-подсказка строятся из него. После каждого нового kind запускать `npm run docs:schema`, чтобы `check:docs` проходил.
- Луна и солнце это примеры, а не обязательные kind: любые фигуры рисуются через `shape` (03-02b).

## Общие правила (на каждое задание)
- Прочитай AGENTS.md, PROJECT_RULES.md, tasks/<файл>. Один коммит на задание: "<номер>: <кратко по-русски>". Push не делать.
- Браузер и Chrome не запускать, процессы не завершать, зависимости не добавлять.
- Перед коммитом: typecheck, build, `npm run check` и проверки задания. Красное не коммитить; после двух неудачных попыток остановиться на задании.
- Имена выходных файлов без символов `<>:"/\|?*`; формат кадра пишется `16x9`, `9x16`.
- Старые сцены, проекты и SHA контактного листа whale-demo не меняются; M0 6/6 EXACT.
- Статусы: «сделано» / «запущено и проверено» / «не проверено».
- Новые kind обязаны: попасть в spec и валидатор, рисоваться в render, иметь позитивные и негативные проверки, фикстуру в scenes/fixtures/ и контактный лист.
