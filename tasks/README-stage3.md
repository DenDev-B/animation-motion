# Очередь этапа 3 «Объекты v1» (03-01 → 03-10)

Порядок строгий. Зависимости: 03-03…03-07 требуют 03-01 и 03-02; 03-09 требует 03-05, 03-07, 03-08; 03-10 требует всех.

## Решения архитектора (не пересматривать без остановки)
- Новые сущности этапа 3 это новые значения `SceneObject.kind`, а не новые типы слоёв. Слой остаётся группой объектов с `depth`. Дискриминатор слоя не вводим.
- Схема сцены остаётся `version: 1`. Добавляются только необязательные поля и новые `kind`. Старые сцены (whale-demo, проект из 2 сцен) остаются валидными и рендерятся побайтно как раньше (сверка с M0 6/6 EXACT и SHA контактного листа не меняются).
- Единицы: условные единицы сцены (высота кадра 1000). Метры вводятся через необязательное `scene.world.unitsPerMeter`.
- Всё детерминировано: никакого Math.random, Date.now, performance.now в engine/. Случайность только через rng(seed). Кадр t не должен зависеть от того, какие кадры рендерились до него.

## Общие правила (действуют в каждом задании)
- Прочитай AGENTS.md, PROJECT_RULES.md, tasks/<файл>. Один коммит на задание: "<номер>: <кратко по-русски>". Push не делать.
- Браузер и Chrome не запускать, процессы не завершать. Зависимости не добавлять.
- Перед коммитом: typecheck, build, `npm run check`, плюс проверки самого задания. Красное не коммитить; после двух неудачных попыток остановиться на задании и записать причину.
- Имена выходных файлов: не использовать символы `<>:"/\|?*` (Windows). Для формата кадра писать `16x9`, `9x16`.
- Статусы в отчёте для каждого пункта: «сделано» / «запущено и проверено» / «не проверено». Не называй проверенным то, что не запускалось.
- Новые kind обязаны: попасть в enum и валидатор (поля, диапазоны, понятные сообщения с путём), рисоваться в render, иметь позитивные и негативные проверки в tools/check-schema.ts, иметь фикстуру-сцену в scenes/fixtures/ и быть видны на контактном листе.
