# Задание 03-02: диапазоны в валидаторе и валидатор каталога

## Цель
Ловить ошибки данных на входе (ИИ позже будет генерировать JSON), не ломая существующие сцены.

## Сделать
1. validateScene: добавить проверки существующих полей с понятными сообщениями и путями:
   - Anim: `period > 0` для bob/swing/pulse; `ease` только из sine|inOut|out|lin (неизвестный ease теперь ошибка); `t0 <= t1` у move/fade; `from/to` у fade в диапазоне 0..1 (если задан); числа конечные.
   - Camera: `zoom > 0`; ключи по возрастанию t (нестрого запрещено, дубль t это ошибка); t в диапазоне 0..duration.
   - Object: `s > 0`, `alpha` в 0..1 (если задан), `depth` слоя конечный.
   - Kinds cloud/skyline/glow: диапазоны params (w,h,r > 0; puffs, windows целые >= 0; minW<=maxW, minH<=maxH; a в 0..1).
   - Style: grain и vignette в 0..1.
   - Palette: слот `sky` не менее 2 цветов; цвета только `#rgb`, `#rrggbb`, `#rrggbbaa` (проверка длины 3/6/8, не 4–5, 7).
2. Неизвестные поля: добавить в результат валидации необязательный список `warnings` (не ошибки) для неизвестных ключей объекта/слоя/сцены. Ошибками они не становятся.
3. validateAsset(json) для catalog/*.json: version, id, name, bounds (4 конечных числа, w>0, h>0), parts не пусто, у каждой части уникальный id, допустимые type (например path, line, circle, как реально используются), поля d/cx/cy/r/off/fill/rim/anim проверяются по типу. Подключить в check-schema и в загрузку каталога в tools/export.ts и tools/contact-sheet.ts.
4. Негативные тесты на каждое новое правило (минимум 20 случаев), позитивный тест на все существующие сцены и проекты.

## Приёмка
- Все существующие scenes/*.json, projects/*.json, catalog/*.json проходят без новых ошибок. Если какая-то существующая сцена теперь невалидна, не править сцену молча: остановиться, записать в отчёт, какое правило и какая сцена, и предложить решение.
- Сверка M0 6/6 EXACT без изменений.

## Не делать
Не менять рендер. Не добавлять новые kind.
