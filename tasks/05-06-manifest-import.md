# Задание 05-06: пакетный импорт по манифесту и стартовый набор

## Цель
Владелец скачивает пачку SVG из бесплатных наборов в папку assets-src/, заполняет один файл-манифест и одной командой добавляет всё в каталог.

## Сделать
1. Формат `assets-src/manifest.json`: массив записей { file, id, name, view, facing?, sizeM, sizeAxis?, tags[], license, author?, source?, url?, attribution?, colors? }. Файл `assets-src/manifest.example.json` с 14 примерными записями (dog, cat, bird, fish, horse, cow, car, bus, plane-side, house, tree, building, boat, person) в статусе «file отсутствует»; `assets-src/README.md` на русском: куда класть SVG, какие поля заполнять, как указывать лицензию (CC0, CC BY 3.0/4.0, own и т.д.), напоминание «проверь лицензию на сайте источника».
2. `npm run catalog:import-manifest -- [путь к manifest.json] [--dry] [--overwrite]`: обрабатывает записи, где файл существует; для отсутствующих выводит «пропущено: нет файла»; ошибки одной записи не останавливают остальные; итоговая таблица «id | результат | предупреждения». Использует importSvg (05-03) и addToCatalog (05-02).
3. Три собственных SVG агента (оригинальные простые: дерево, автомобиль, дом в разрезе) в assets-src/own/ с лицензией own и записями в manifest.example.json, импорт которых даёт реальные модели каталога tree-simple, car-simple, house-simple (view side, размеры в метрах правдоподобны: дерево 8 м, автомобиль 4.5 м, дом 7 м).
4. `npm run credits` (из 05-01) работает на проекте, использующем эти модели; пример текста титров в docs/examples/credits-example.txt.
5. .gitignore: assets-src/*.svg НЕ игнорировать только для own/; скачанные владельцем SVG по умолчанию в git не попадают (assets-src/downloads/ в .gitignore), каталог/ хранит уже импортированные модели вместе с лицензией.

## Приёмка
`npm run check` PASS (тест на dry-run манифеста с отсутствующими файлами и с тремя собственными), M0 6/6 EXACT.

## Не делать
Не скачивать файлы из сети, не добавлять чужие SVG в репозиторий.
