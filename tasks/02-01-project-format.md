# Задание 02-01: формат проекта (JSON) и валидатор

## Цель
Проект = один JSON с несколькими сценами по порядку. Это контракт для редактора, экспорта и будущего ИИ-слоя. Схема сцены v1 НЕ меняется.

## Контракт ProjectV1
```
{
  "version": 1,
  "title": "Что если бы киты летали",
  "fps": 30,
  "format": "16:9",            // "16:9" | "9:16"
  "scenes": [
    {
      "id": "s1",              // уникальный в проекте
      "name": "Закат над городом",
      "scene": { ...SceneV1... },   // сцена встроена целиком (проект переносимый)
      "transition": { "type": "cut" }   // пока только cut; поле зарезервировано под этап 3
    }
  ]
}
```
Длительность сцены берётся из scene.duration. Число кадров сцены = round(duration * fps), время кадра внутри сцены t = i / fps.

## Файлы
- engine/project.ts: типы ProjectV1, validateProject(json) -> {ok, errors[]}, migrateProject(json) (пока заглушка для version 1), хелперы projectFrameCount(project), locateFrame(project, globalIndex) -> {sceneIndex, t}.
- Валидатор переиспользует существующий validateScene для каждой сцены; ошибки с путём вида `scenes[2].scene.layers[0].id`.
- projects/whale-demo.project.json: проект из 2 сцен (текущая demo-сцена и её копия с другой палитрой/длительностью), id разные.
- tools/check-project.ts и npm script `check:project`; включить в `npm run check`.
- Тесты в стиле существующих check-скриптов: валидный проект, дубль id сцены, пустой список сцен, неверный fps, неверный format, сломанная вложенная сцена.

## Критерии приёмки
- check:project: валидный проект PASS, каждый негативный случай даёт ожидаемую ошибку с путём.
- locateFrame: для проекта из двух сцен границы кадров проверены (последний кадр сцены 1, первый кадр сцены 2).
- engine/ остаётся без DOM, window, Math.random, Date.now, performance.now.
