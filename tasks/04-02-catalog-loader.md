# Задание 04-02: единый каталог приложения и миграция моделей

## Сделать
1. `catalog/index.json`: генерируется `npm run catalog:index` из catalog/*.json (id, name, file, tags, view, realSize, hasPoses, clips[], license). `npm run check:catalog` проверяет, что индекс актуален и все модели проходят validateAsset (в `npm run check`).
2. Загрузчик `engine/catalog.ts` (чистые функции без DOM/Node: принимает уже прочитанные JSON): `resolveAsset(id, scene, catalogMap)`: сначала scene.assets (переопределение), затем каталог; если id не найден, ошибка валидатора со списком доступных id (первые 20). Node-обёртка читает папку catalog/; редактор берёт список с dev-сервера (эндпоинт GET /api/catalog из 04-03; до него временно из статического импорта индекса). Валидатор сцены принимает ссылку на asset из каталога без копии в scene.assets.
3. Миграция существующих моделей: каждая модель получает `meta` (view, facing, tags на русском и английском, license.name = "own" (собственная работа проекта), anchor при необходимости). whale: realSize.widthM=15 (если ещё не сделано в 04-00); добавить 2 позы «хвост-вверх» и «хвост-вниз» (смещение/поворот части tail, без изменения базового вида) и клип «плыть» (period 2.4 с), совместимый с текущей анимацией. Текущая сцена whale-demo продолжает использовать старые partAnim и не меняется.
4. Проверка переносимости проекта: `npm run project:bundle -- <project.json>` создаёт копию с встроенными использованными моделями (scene.assets), чтобы проект можно было отдать без каталога. Копия валидна и рендерится идентично оригиналу (EXACT по кадрам 0, середина, последний).
5. ai:prompt для сцены/проекта вместо вставки полных моделей добавляет «Доступные модели каталога» (id, name, tags, view, realSize, clips) одной строкой на модель, чтобы ИИ мог ссылаться на них по id; размер промта проекта stage3-demo не должен вырасти больше чем на 3 КБ.

## Приёмка
M0 6/6 EXACT, SHA whale-demo прежний, check:catalog PASS, bundle EXACT, `npm run check` PASS.

## Не делать
