# Задание 04-03: добавление модели в каталог (CLI и dev-сервер)

## Сделать
1. `npm run catalog:add -- <файл|-> [--id slug] [--overwrite] [--dry]`: читает ответ ИИ или JSON (терпимо через extractJson), валидирует (validateAsset + обязательные для каталога поля: id, name, meta.view, meta.license.name, realSize хоть по одному измерению), приводит id к виду `[a-z0-9-_]` (транслит кириллицы допустим), при занятом id добавляет суффикс _2 (или перезаписывает с `--overwrite`), пишет catalog/<id>.json (UTF-8, форматирование 2 пробела), обновляет index.json. `--dry` только проверяет и печатает, что будет сделано. При ошибках: понятный русский список и out/ai/model-fix-request.md (buildModelFixRequest из 04-05 если уже есть, иначе общий buildFixRequest).
2. Dev-сервер Vite: небольшой плагин в vite.config (без новых зависимостей): `GET /api/catalog` (индекс и модели), `POST /api/catalog/add` (тело = JSON {model, overwrite?}; тот же код, что в CLI, общая функция). Безопасность: слушать только localhost; запись только в catalog/; id по маске; тело до 2 МБ; не принимать пути из запроса; ответ со списком ошибок или id сохранённой модели. В production-сборке эндпоинтов нет.
3. Проверки (без браузера): юнит-тесты общей функции addToCatalog (позитив, дубль id, overwrite, плохой id, нет license, обрезанный JSON, слишком большая модель), тест плагина через вызов обработчика с подделанным req/res (если без запуска сервера невозможно, статус «не проверено» и ручной шаг для владельца).
4. Старые модели не затрагиваются; `npm run check` PASS; check:catalog PASS.

## Приёмка
Тесты PASS; запись в catalog/ создаёт валидный файл и обновляет index.json; повторный `catalog:add` того же файла не ломает каталог.

## Не делать
Не открывать порты наружу, не принимать запросы не с localhost, не писать вне catalog/.
