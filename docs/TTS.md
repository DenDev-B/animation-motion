# Озвучка (TTS)

Сцене голос даёт одно из трёх. Все три попадают в проект одинаково: `scenes[].voice.file` — путь относительно `audio/`, `voice.words` — тайминг слов.

1. **Свой файл** — владелец записал речь сам, положил wav в `audio/` и вписал `voice.file`. Никаких программ не нужно, это не «адаптер».
2. **Piper** — локальная нейросеть, которую мы вызываем как внешнюю команду.
3. **Голос Windows (SAPI)** — `System.Speech` через PowerShell; говорит тем голосом, который установлен в системе.

Облачных и платных TTS в проекте нет.

## `npm run tts`

```
npm run tts -- --project projects/X.project.json [--scene N | --all] [--adapter piper|sapi] [--force] [--lang ru]
```

Берутся сцены, у которых заполнен `voice.text` (нумерация сцен с единицы; без `--scene` — все сцены сразу). Дальше:

- файл кладётся в `audio/tts/<хэш>.wav`, где имя — первые 12 символов `sha1` от «адаптер + голос + язык + текст». Один и тот же текст тем же голосом даёт одно и то же имя.
- такой файл уже есть — синтез пропускается (кэш); `--force` перезаписывает.
- длительность готового файла мерится `ffprobe`, по ней считается `voice.words`.
- в проект записываются только `voice.file` и `voice.words`. `offset`, `gain`, `text` и порядок всех полей остаются как были; файл меняется атомарно (временный файл + переименование) и только если результат проходит `validateProject`.
- если голос длиннее сцены (с учётом `offset`), будет предупреждение «голос длиннее сцены на N с». Длительность сцены `tts` не меняет — её увеличивает человек.

Адаптер не указан — берётся первый доступный по порядку Piper → SAPI; недоступен ни один — команда объясняет почему.

## В редакторе

Вкладка «Склейка», у каждой сцены — раскрывающийся блок «Озвучка»: текст (до 2000 символов), сдвиг, громкость, голос и кнопки «Озвучить» / «Убрать звук». Синтез идёт через локальный сервис (`/__api/tts/synthesize`, только при запуске через `run.bat`); готовый файл сразу проигрывается в плеере блока.
Рядом — «Музыка проекта»: файл из `audio/`, громкость и «Приглушать под голосом». Это `project.audio.music`, отдельного файла в проекте нет.
`/__api/audio/list` отдаёт пути относительно `audio/` без длительностей (панели они не нужны, `ffprobe` на каждый файл не гоняем); `/__api/audio/file` раздаёт байты с поддержкой Range, чтобы плеер мог перематывать.
Правки идут тем же путём, что и остальной проект: история, флаг изменений, автосохранение в браузере. Сам проект на диск редактор не пишет — его скачивает кнопка сохранения.

## Пакетная озвучка (все сцены)

`npm run tts -- --all` (или без `--scene`) озвучивает все сцены с `voice.text`, у которых ещё нет `voice.file`, последовательно. Сцены без `voice.text` и сцены с готовым `voice.file` пропускаются — наличие `voice.file` именно того, что считается «сцена уже озвучена». Чтобы переозвучить сцену, нужно сначала убрать звук (`voice.file`) на её карточке. Ошибка одной сцены не останавливает остальные — каждая сцена получает свой результат (или свою ошибку) в карточке.

## Оценка длительности речи

`estimateSpeechSec(text, lang)` считает время чтения текста: деление на ставку (русский ~2.6 слова/с, иное ~2.8; язык определяется `speechLangOf` по наличию кириллицы в тексте) плюс паузы на `. ! ? …` (конец фразы) и `, ; :` (внутрифразовая). В проектах от ИИ `scene.duration` автоматически увеличивается под `voice.text` + 0.4 с, и это фиксируется замечанием при проверке проекта.

## Piper

```
pip install piper-tts
python -m piper.download_voices <имя_голоса>
```

Настройки — в `.env.local` (это не секреты, читаются тем же способом, что и модели AI):

| Переменная | Смысл |
|---|---|
| `PIPER_CMD` | команда запуска; по умолчанию `piper`, можно `python -m piper` |
| `PIPER_MODEL` | путь к файлу голоса `.onnx` (рядом лежит его `.onnx.json`) |

Текст передаётся процессу через stdin в UTF-8, а не аргументом командной строки. Флаги взяты из документации Piper (`--model`, `--output-file`); если ваша версия Piper спорит с командой запуска, покажите вывод `piper --help` — подстроим.

## Голос Windows (SAPI)

Работает только на Windows, ничего ставить не надо. Язык задаётся флагом `--lang` (`ru`, `uk`, `en`) и сравнивается с культурой установленного голоса. Подходящего голоса нет — команда честно скажет: «в Windows нет русского голоса: Параметры → Время и язык → Речь». Текст в командную строку не попадает: он пишется во временный файл в UTF-8, скрипт читает его сам.

## Тайминги слов

`voice.words` — оценка по длине текста: длительность звука делится между словами пропорционально числу букв и цифр, после запятой и точки добавляется пауза. Это не выравнивание по реальной речи: для точных таймингов файл озвучки надо размечать отдельно.

## Субтитры

Необязательное поле `project.subtitles` включает субтитры из `voice.words`: слова собираются в реплики до `maxWords` (1..6), конец фразы — точка, `!`, `?` или `…`. Время реплики — от первого слова до последнего с учётом `voice.offset` и наложений переходов; реплики за концом ролика обрезаются.
Реплики рисуются на итоговом кадре (и в экспорте, и в превью «Склейки») и выгружаются рядом с MP4 отдельным файлом `.srt`; в режиме куска тайминги сдвигаются на начало окна.
`position` — `bottom`, `center` или `top` с учётом безопасных зон площадки; `size` — высота шрифта как доля высоты кадра (по умолчанию 0.055 для 16:9 и 0.045 для 9:16); `upper` печатает заглавными; `enabled: false` выключает субтитры, не удаляя настройки.
Панель «Субтитры» — во вкладке «Склейка» под музыкой; сцены с текстом без таймингов она отмечает подсказкой «озвучьте их».

## Проверка доступности

```
npm run tts:doctor
```

По каждому адаптеру: `OK` или причина по-русски. Ничего не синтезирует и проект не трогает.
