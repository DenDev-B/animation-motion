# Банк идей: что можно взять и откуда (комбайн для роликов)

Сюда складываем всё, что нашли в чужих проектах, видео и статьях и что можно взять для улучшения нашего комбайна. Файл живёт в репозитории как `docs/IDEAS.md`. Правило: сначала запись сюда, решение «берём» принимаем позже, при планировании этапа.

## Как вести
- Одна идея = одна строка в таблице ниже + при необходимости подробности в разделе «Заметки».
- **Лицензия** указываем обязательно. MIT/Apache/CC0 можно брать код с сохранением нотисов. «All rights reserved» или неизвестно = только идея, код переписываем сами.
- **Статус**: `идея` → `изучить` (агенту дана задача-разведка) → `берём` (в плане этапа) → `сделано` / `отказ` (с причиной).
- Всё, что скопировано в репозиторий, дополнительно записываем в `THIRD_PARTY.md` (источник, версия, лицензия, что взяли).
- Код чужих репозиториев сначала читаем, а уже потом решаем. По README мы его не оценивали.

### Breakout Motion v2.1.0: что внутри и что проверено
- **Что это.** Навык для ИИ-агентов (`SKILL.md` + 12 справочников + 7 скриптов + `CHANGELOG.md`, 280 КБ, на русском). Цель: motion-ролики из HTML/Canvas/WebGL → MP4 с машинной приёмкой. Переименован из `vizavi-motion`.
- **Происхождение и лицензия.** Файла LICENSE нет, автор не указан. Часть справочников адаптирована из чужих архивов `higgsfield-motion*.skill` (сам автор пишет, что это не официальные материалы), «девять канонических стилей курса» пересказаны из курса. Архив получен по ссылке, которую автор сам оставил под видео, то есть получен законно. Но разрешение копировать код в чужие проекты нигде не прописано, поэтому по правилу проекта пока только идеи, формулировки пишем свои. Чтобы снять вопрос, можно спросить автора (комментарий под видео); если разрешит, записываем это в `THIRD_PARTY.md` и берём код.
- **Проверено запуском** (облачная песочница, Node 22, ffmpeg 6.1, Chromium): `render_frames.mjs` (вместе с `frame_diff.mjs`), `mux.sh`, `verify_export.py` на их примере `contract-example.html` (2 с, 960×540, 30 fps, тестовый звук): 60 кадров без пропусков, воспроизводимость по состоянию подтверждена, приёмка файла 13 ok / 0 FAIL. **Не запускал:** `contact_sheet.sh`, `audio_accents.py`. Скрипты проверены поиском сетевых и разрушающих вызовов: только localhost для управления Chrome, удаляются лишь свой каталог кадров и временный профиль.
- **Что мешает взять как есть (Windows у владельца).** Поиск Chrome описан только для macOS/Linux (на Windows нужен `CHROME_PATH` или `--chrome`); `mux.sh` и `contact_sheet.sh` написаны на bash; `verify_export.py` и `audio_accents.py` на Python; под root в Linux Chrome требует `--no-sandbox`, флага нет (в песочнице обошёл обёрткой). Вывод: берём идеи и пишем свои Node-версии в `tools/` (Node и ffmpeg у владельца уже стоят).
- **Не берём.** Генерация изображений (Krea, Cloudflare Workers AI и др.) — у нас графика из кода. Девять стилей курса и демо из шести частей — чужой учебный контент. Дефолт автора 1080p60 — вдвое больше кадров, чем при 30 fps; fps выберем сами на этапе 1.

### Предложение для этапа 0–1: сохранить три пути экспорта
- Дёшево и ничего не ломает: `engine/` не трогает `document` и `window`, а принимает контекст и размер: `renderFrame(ctx, scene, t, size)`.
- Тогда на этапе 1 остаются открытыми три пути: **A** Chrome/CDP со скриншотами (#17, без зависимостей, самый медленный), **B** Canvas в Node + поток кадров в ffmpeg (новая зависимость, нужно согласование), **C** WebCodecs (#1).
- Задача-разведка этапа 1: замерить A/B/C на ноутбуке владельца (Windows, RTX 3050 4 ГБ) на одной и той же сцене.

### Про озвучку
- Озвучка делается отдельно. Сцена и ролик ссылаются на файл дорожки; графика не зависит от голоса.
- У Timeline Studio встроенный TTS: английский (Kokoro), несколько европейских языков (Piper), китайский. Русский и украинский там не заявлены.

### Что пока не делаем
- Монтаж реальных съёмок (нарезка пауз, зумы, b-roll). Это не наше ядро: у нас графика из кода.
- Аватары и lip-sync (digital human в Timeline Studio) — слишком тяжело для слабого железа и требует отдельного изучения лицензий и ответственного использования.
